# 学生の手順（はじめての人へ）

この手順書は、このリポジトリで初めて開発する学生のためのものである。上から順に進めれば、自分の PC で動かし、最初の変更を先生に出すところまでできる。決まりの一覧は [CONTRIBUTING.md](../CONTRIBUTING.md) にある。

わからないところで止まったら、無理に進めずに先生に聞く。聞くときは、**実行したコマンド**と**出てきた文（エラー）**をそのまま見せる。

## 0. 全体の流れ

```
 1. 準備（最初の 1 回だけ、2〜3 時間）
    GitHub のアカウント → ソフトを入れる → リポジトリを取る → コンテナを作る → turtlesim で動かす
 2. 練習（30 分）
    動作確認の記録に 1 行足して、初めての PR を出す
 3. ふだんの作業（課題ごとに繰り返す）
    Issue → ブランチ → 作る → コミット → push → PR → 先生が確かめる → main に入る
```

言葉の意味は次のとおりである。

| 言葉 | 意味 |
|---|---|
| リポジトリ | プログラムと書類一式の置き場所。GitHub にある |
| main | みんなで使う正式版。直接は書き換えない |
| Issue | やることを書いた付箋。GitHub の Issues タブにある |
| ブランチ | main を写した自分用の作業場。ここで書き換えても main は変わらない |
| コミット | 作業場の変更を、手元の PC に区切りとして保存すること |
| push | 手元のコミットを GitHub に送ること。送るまでは先生に見えない |
| PR（プルリクエスト） | 「この作業場の変更を main に入れてください」という依頼。先生が中身を見て、承認すると main に入る |

## 1. 準備（最初の 1 回だけ）

### 1.1 GitHub のアカウントを作る

1. https://github.com/signup でアカウントを作る。ユーザ名は公開されるので、**本名や学籍番号を使わない**。
2. **メールアドレスを非公開にする。** コミットには書いた人のメールアドレスが記録され、誰でも見られる。https://github.com/settings/emails を開き、「Keep my email addresses private」に印を付ける。その下に出る `数字+ユーザ名@users.noreply.github.com` を、1.3 で使うので控えておく。
3. ユーザ名を先生に伝える。先生が招待すると、GitHub に登録したメールに招待が届くので、「**Accept invitation**」を押す。これでリポジトリに push できるようになる。

### 1.2 ソフトを入れる

| ソフト | 何に使うか | Mac | Windows |
|---|---|---|---|
| Git | 変更の記録と、GitHub とのやり取り | ターミナルで `xcode-select --install` | https://git-scm.com/download/win （途中の選択はすべてそのまま） |
| GitHub CLI（`gh`） | GitHub へのログイン | https://cli.github.com のダウンロード | 同じ |
| Python 3 | 公開してはいけない情報の検査（`tools/check_secrets.py`） | Git と一緒に入る（`python3 --version` で確かめる） | https://www.python.org/downloads/ （最初の画面で「Add python.exe to PATH」に印を付ける） |
| Docker Desktop | ROS 2 の入ったコンテナを動かす | https://www.docker.com/products/docker-desktop/ | 同じ（WSL 2 を使う設定のまま入れる） |
| Google Chrome | コンテナの画面と、カメラの映像を送るページを開く | https://www.google.com/chrome/ | 同じ |
| Visual Studio Code（あると便利） | プログラムを書く | https://code.visualstudio.com | 同じ |

- **Windows では、この手順書のコマンドを「Git Bash」で実行する**（Git と一緒に入る。スタートメニューから開く）。
- 入れたら、ターミナル（Windows は Git Bash）で次を実行し、版の番号が出ることを確かめる。

  ```bash
  git --version
  python3 --version
  gh --version
  docker --version
  ```

- Docker Desktop は、使う前に起動しておく（メニューバーやタスクバーにクジラのアイコンが出る）。

### 1.3 Git に名前とメールを教える

コミットに記録される名前とメールである。名前は GitHub のユーザ名、メールは 1.1 の 2. で控えた noreply のアドレスにする。

```bash
git config --global user.name "GitHubのユーザ名"
git config --global user.email "数字+ユーザ名@users.noreply.github.com"
```

### 1.4 GitHub にログインする

```bash
gh auth login
```

質問には次のように答える（矢印キーで選び、Enter）。

| 質問 | 答え |
|---|---|
| Where do you use GitHub? | GitHub.com |
| What is your preferred protocol for Git operations? | HTTPS |
| Authenticate Git with your GitHub credentials? | Yes |
| How would you like to authenticate? | Login with a web browser |

画面に出る 8 文字のコードを控えて Enter を押すと、ブラウザが開く。コードを入れて「Authorize」を押す。ターミナルに「Logged in as ユーザ名」と出れば終わりである。

### 1.5 リポジトリを取る（clone）

置きたい場所に移ってから取る。ここではホームの下の `dev` フォルダに置く例を示す。

```bash
mkdir -p ~/dev && cd ~/dev
git clone https://github.com/ba2vwbus13/chibariyo-dance-mimic.git
cd chibariyo-dance-mimic
```

`chibariyo-dance-mimic` というフォルダができ、中にプログラム一式が入る。**これから先のコマンドは、このフォルダで実行する。**

### 1.6 コンテナを作る

ROS 2 と MediaPipe の入ったコンテナを作る。初回はインターネットから約 3 GB を取るので、20〜30 分かかる。学校の Wi-Fi が遅いときは、有線か家で行う。

```bash
cd docker && docker compose up -d --build && cd ..
```

終わったら、Chrome で http://localhost:6081 を開く。Ubuntu のデスクトップが出る。デスクトップの Terminator（端末）を開き、次を実行してプログラムをビルドする。

```bash
cd ~/ros2_ws && colcon build --symlink-install
```

ダンスの物真似で使う動画も取っておく（自分の PC のターミナルか Git Bash で、リポジトリのフォルダで実行する）。

```bash
tools/download_videos.sh
```

### 1.7 turtlesim で動かす

コンテナの Terminator で、ダンスの動画に合わせて亀を踊らせる。

```bash
source ~/ros2_ws/install/setup.bash
ros2 launch finger_dance pose_dance.launch.py turtlesim:=true
```

亀の画面と、体の点を描いた画面が出て、亀が左右に揺れれば成功である。`Ctrl + C` で止める。

指ダンスも試す。

```bash
ros2 launch finger_dance finger_dance.launch.py turtlesim:=true
```

自分の PC の Chrome で http://localhost:6081/camera.html?port=9091 を開き、カメラを選んで 10 fps にし、「開始」を押す。人差し指を立てて向きを変えると亀が走り、グーで止まる。

ここまでできたら、準備は終わりである。

### 1.8 人追従を担当する人だけ：Gazebo のコンテナを作る

人追従（`follow/`）は、指ダンス・ダンスの物真似とは別のコンテナ（ROS 2 Humble ＋ Gazebo Fortress）で動かす。

1. Docker Desktop の Settings → Resources で、メモリを **8 GB 以上**にする（足りないと、作る途中で止まる）。
2. コンテナを作る。初回は 20〜40 分かかる。

   ```bash
   cd follow && docker compose up -d --build && cd ..
   ```

3. Chrome で http://localhost:6080 を開き（指ダンスは 6081、こちらは 6080）、Terminator でビルドする。

   ```bash
   cd ~/ros2_ws && source /opt/ros/humble/setup.bash && colcon build --symlink-install
   ```

4. 骨格で人を追いかけるシミュレーションを動かす。

   ```bash
   source ~/ros2_ws/install/setup.bash
   ros2 launch wheelchair_gazebo demo.launch.py method:=pose
   ```

   Gazebo の画面に車いすと人が出て、人が歩き出すと車いすが付いていけば成功である。骨格の検出に MediaPipe を使うので、初回はコンテナに MediaPipe とモデルを入れる必要がある（[follow/README.md](../follow/README.md) と先生に確かめる）。

方式・計測の方法・これまでの結果は、`follow/docs/解説資料_人混み追従.pdf` にまとめてある。

## 2. 練習：初めての PR を出す

[docs/動作確認.md](動作確認.md) の表に、自分の行を 1 行足して PR を出す。どの PC で動いたかの記録にもなる。

1. **main を最新にする。** ほかの人の変更を取り込む。

   ```bash
   git switch main
   git pull
   ```

2. **作業場（ブランチ）を作る。** 名前は `practice-ユーザ名` にする。

   ```bash
   git switch -c practice-ユーザ名
   ```

   `Switched to a new branch` と出れば、作業場に移っている。今いる作業場は `git status` の 1 行目でいつでも確かめられる。

3. **ファイルを書き換える。** VS Code などで `docs/動作確認.md` を開き、表の最後に 1 行足して保存する。

   ```
   | ユーザ名 | 2026-11-10 | Mac（M2） | OK | OK | 特になし |
   ```

4. **変えたところを確かめる。**

   ```bash
   git status
   git diff
   ```

   `git diff` で、足した行が緑の `+` で表示される（`q` で戻る）。

5. **公開してはいけない情報がないか調べてから、コミットする。**

   ```bash
   python3 tools/check_secrets.py
   git add docs/動作確認.md
   git commit -m "動作確認の記録にユーザ名の行を足す"
   ```

   Windows で `python3` が見つからないときは `python` で試す。

6. **GitHub に送る（push）。** 初めて送るブランチなので `-u` を付ける（2 回目からは `git push` だけでよい）。

   ```bash
   git push -u origin practice-ユーザ名
   ```

7. **PR を作る。** https://github.com/ba2vwbus13/chibariyo-dance-mimic を開くと、黄色い帯に「**Compare & pull request**」が出るので押す。
   - タイトル：コミットのメッセージと同じでよい。
   - 本文：ひな形の「何を変えたか」「どう確かめたか」を書き、「確認」の欄の当てはまるものに `x` を入れる（`- [x]`）。
   - 「Create pull request」を押す。
8. **自動の検査を待つ。** PR の画面の下に、検査（check）の結果が出る。数分で緑の ✓ になる。赤の ✕ のときは「Details」を押して理由を読み、直す（4 章）。
9. **先生の確認を待つ。** 先生がコメントを付けたら、同じ作業場で直して、3.〜6. と同じようにコミットして `git push` する。PR に自動で足される。先生が承認して「Merge」を押すと、main に入る。
10. **後片付け。** main に戻って最新にし、使い終わった作業場を消す。

    ```bash
    git switch main
    git pull
    git branch -d practice-ユーザ名
    ```

## 3. ふだんの作業

課題ごとに、練習と同じ流れを繰り返す。

1. **Issue を選ぶ。** GitHub の Issues タブで、先生が立てた課題を選び、右の「Assignees」に自分を入れる。やりたいことを思い付いたら、自分で Issue を立てて先生に相談する。
2. **main を最新にして、作業場を作る。** 名前は、内容がわかる短い英語にする（例：`two-hands`、`fix-timeout`）。

   ```bash
   git switch main && git pull
   git switch -c two-hands
   ```

3. **作って、確かめる。** turtlesim や `--dry-run` で動きを確かめる。コンテナの中の `~/ros2_ws` は、自分の PC の `ros2_ws` と同じフォルダなので、VS Code で書き換えるとすぐにコンテナに反映される（ファイルを足したときと `setup.py` を変えたときは `colcon build` をし直す）。
4. **こまめにコミットする。** 区切りのよいところで、1 つのまとまりごとにコミットする。

   ```bash
   python3 tools/check_secrets.py
   git add 変えたファイル
   git commit -m "何をしたかを日本語で 1 行"
   ```

5. **push して PR を出す。** PR の本文に `#Issueの番号` を書くと、Issue とつながり、main に入ったときに Issue が自動で閉じる（例：`Closes #3`）。
6. **先生とやり取りして直す → main に入る → 後片付け。**

## 4. 困ったとき

| 起きたこと | どうするか |
|---|---|
| `git push` で `protected branch` や `rejected` と出る | main にいるまま push している。`git switch -c 新しい作業場の名前` で作業場を作ってから push する（作業場を作ると、それまでのコミットも作業場に入る） |
| `git pull` で `Your local changes would be overwritten` と出る | 保存していない変更がある。コミットするか、要らなければ先生に聞いてから戻す |
| `CONFLICT`（衝突）と出る | ほかの人と同じ行を書き換えている。あわてずに先生を呼ぶ |
| 検査が ✕：公開してはいけない情報 | 「Details」に出たファイルと行を直す。IP アドレスは `<ロボットのIP>` のように書く。直してコミットし、`git push` |
| 検査が ✕：Python の文法 | 「Details」に出たファイルと行の書き間違いを直す |
| http://localhost:6081 が開かない | Docker Desktop が起動しているか。`docker ps` に `finger_dance` が出るか。出なければ `cd docker && docker compose up -d` |
| `Permission denied` で push できない | 招待を受けたか（1.1 の 3.）。`gh auth status` でログインしているか |
| どの作業場にいるかわからない | `git status` の 1 行目を見る |

## 5. やってはいけないこと

- main で直接作業する（必ず作業場を作る）。
- `git push --force`、`git reset --hard` を使う（ほかの人の作業や自分の作業が消える）。使いたくなったら先生に聞く。
- IP アドレス、Wi-Fi の名前とパスワード、メールアドレス、名前、学籍番号、顔の写った写真を入れる。
- 動画や rosbag などの大きなファイルを入れる。
- 先生がいないときに、実機（chibamouse1、WHILL）を動かす。
