# 指の動きで Raspberry Pi Mouse を踊らせる（finger_dance）

作成：2026-10-20（Mac Studio）

**設計書と操作手順書は `docs/設計書.pdf`・`docs/操作手順書.pdf` にまとめた（元の HTML と図は `docs/`。図は `docs/make_figures.py` で作る）。** この README は作業の記録である。

カメラに映った手の形と人差し指の向きを MediaPipe（Hand Landmarker）で検出し、その動きに合わせて Raspberry Pi Mouse を走らせる・旋回させる・踊らせる仕組みである。最終的には伴走型スマート車いす「チバリヨカー」で同じことをする（10章）。まずは turtlesim で確かめ、次に Raspberry Pi Mouse の実機で試す。

身体全体の姿勢（MediaPipe Pose）から動きを写すのは難しいので、まずは指の動きで操縦する方式にした。

## 1. 姿勢（指）から動きへの対応表

| 手の形 | ロボットの動き |
|---|---|
| **人差し指だけを伸ばす** | **指の向きで走る**（下の表）。指を動かすと、それに合わせてロボットの動きが変わる |
| **チョキ**（人差し指と中指） | **踊る**：その場で左右に小刻みに振る（0.4秒ごとに左右を入れ替える。最初の半周期だけ左に回るので、元の向きを中心に振れる） |
| グー | 停止 |
| パー | 停止 |
| その他の形（中指だけ、など） | 停止 |
| 手が映っていない | 停止 |
| 検出結果が 0.5秒 届かない（カメラや検出ノードが止まった） | 停止 |

人差し指の向き θ（0° = 真上、+ = 本人から見て左、− = 本人から見て右、±180° = 真下）と動き。ジョイスティックのように、前後 = 最大速度 × cos θ、旋回 = 最大角速度 × sin θ とする。

| 指の向き θ | 前後 | 旋回 | 実機の値の例（最大 0.05 m/s・1.0 rad/s） |
|---|---|---|---|
| 真上（−10°〜+10°） | 前進 | しない | 0.05 m/s |
| 左に傾ける（+10°〜+70°） | 前進（傾けるほど遅く） | 左旋回（傾けるほど速く） | 30° で 0.043 m/s・0.50 rad/s |
| 真横の左（+70°〜+110°） | しない | 左旋回（その場で回る） | 90° で 1.0 rad/s |
| 左下（+110°〜+170°） | 後退 | 左旋回 | 150° で −0.043 m/s・0.50 rad/s |
| 真下（±170°〜180°） | 後退 | しない | −0.05 m/s |
| 右側（−10°〜−170°） | 左側と同じ | **右旋回** | |

- 「左」は、本人から見た左（ロボットが本人と同じ向きを向いている場合の、ロボットの左）とする。ロボットが本人と向かい合っているときに鏡のように動かしたい場合や、カメラの映像が左右反転している場合は、`mirror:=true` で左右を入れ替える。
- 親指は、伸ばしているかどうかの判定が手の向きによって不安定なので使わない（グーでもパーでも、親指の状態は問わない）。
- 安全のため、走り出す形（人差し指・チョキ）は**2回続けて**同じ形を検出したときに切り替え、止まる形はすぐに切り替える。
- 速さの上限は、実機では前後 0.05 m/s・旋回 1.0 rad/s・踊り 1.0 rad/s とした（専攻科実験 R1 で、タイヤが滑るので 0.05 m/s 以下にしたのに合わせた）。turtlesim では 1.0・1.5・3.0 である。

### 指の判定の方法

MediaPipe の Hand Landmarker が出す手の21点のうち、手首（0）と各指の第2関節・指先を使う。**手首から指先までの距離が、手首から第2関節までの距離の 1.1倍より長い指を「伸ばしている」**と判定する（`ext_ratio`）。距離で比べるので、手を横や下に向けても判定できる。人差し指の向きは、人差し指の付け根（5）から指先（8）への向きである。

## 2. 仕組み

```
PC（Mac Studio）                                                      chibamouse1（Raspberry Pi Mouse V3 ＋ Pi 3）
 ブラウザ camera.html ─(rosbridge 9091)→ /image_raw/compressed
   （Studio Display のカメラ）               │
                                         finger_detect（MediaPipe Hand Landmarker）
                                             │ /finger_gesture（String、JSON：形・向き）
                                             │ /finger_image/compressed（検出結果の画像 → rqt_image_view）
                                         finger_dance（対応表）
                                             │ /cmd_vel（TwistStamped）、/motor_power ──(rmw_zenoh、Wi-Fi)──→ raspimouse ノード
                                             └ /turtle1/cmd_vel（Twist）→ turtlesim（turtlesim:=true のとき）
```

- Docker のコンテナ（ROS 2 Jazzy）の中で動かす。中身は専攻科実験 2026 の環境（`授業/13専攻科実験/2026/手順書/docker`）のうち必要なものに MediaPipe とモデルを足したもので、実機との通信（`robot_connect`）、ROS_DOMAIN_ID の保存（`set_domain_id`）、カメラの送信（`camera.html`）は専攻科実験と同じである。**専攻科実験とは分けてある**：`robot.bash` と `camera.html` は研究フォルダに写し、元の公開イメージ（`tiryoh/ros2-desktop-vnc:jazzy`）から直接ビルドする（版はダイジェストで固定）。授業のフォルダやイメージを変えても影響を受けない。
- Docker Desktop のコンテナからは PC のカメラを直接使えないので、ブラウザでカメラの映像を JPEG にして rosbridge で送る（専攻科実験 R3 と同じ）。
- MediaPipe は Pi 3 では重すぎるので、PC で動かす。Wi-Fi に流れるのは速度の指令だけである。
- ロボットも研究専用の **chibamouse1**（Raspberry Pi Mouse V3 ＋ Pi 3、<ロボットのIP>）とし、授業用の pimouse1〜3 とは分ける。Wi-Fi ルータも研究用の `<研究用ルータのSSID>` を研究室に置き、授業用の `<授業用ルータのSSID>` とは分ける。作り方は `chibamouse/作り方.md`。
- ROS_DOMAIN_ID は **30** とした（`ros2_ws/ros_domain_id.txt`）。同じ Mac で動いているほかのコンテナとトピックが混ざらないようにするためである。ロボット側も 30 にする。
- ポートは noVNC が **6081**、rosbridge が **9091** である。専攻科実験のコンテナ（6080・9090）や、`wheelchair_follow`（6080）と同時に動かせるようにした。

## 4. 準備（初回だけ）

1. コンテナを作って起動する（元のイメージ（約3GB）、MediaPipe、モデルのダウンロードにインターネットが必要）。

   ```bash
   cd chibariyo-dance-mimic/docker && docker compose up -d --build
   ```

2. ブラウザで http://localhost:6081 を開き、デスクトップの Terminator でパッケージをビルドする。

   ```bash
   cd ~/ros2_ws && colcon build --symlink-install
   ```

   `--symlink-install` なので、Python のファイルを書き換えたときはビルドし直さなくてよい（ファイルを足したとき、`setup.py` を変えたときはビルドし直す）。

## 5. 起動手順：turtlesim で確かめる

1. Terminator で次を実行する（rosbridge、`finger_detect`、`finger_dance`、turtlesim、rqt_image_view が起動する）。

   ```bash
   source ~/ros2_ws/install/setup.bash
   ros2 launch finger_dance finger_dance.launch.py turtlesim:=true
   ```

2. Mac のブラウザ（Chrome）で **http://localhost:6081/camera.html?port=9091** を開き、カメラに「Studio Display のカメラ」を選び、フレームレートを **10 fps** にして「開始」を押す（カメラの使用を許可する）。
3. カメラに手を向ける。rqt_image_view に手の点と判定（`point +23deg` など）が出る。人差し指を立てて向きを変えると亀が走り、チョキで左右に振れ、グー・パーで止まる。端末には形が変わったときだけ「人差し指：指の向きに走る」などと表示される。
4. 終わるときは、ブラウザの「停止」を押し、端末で `Ctrl + C` を押す。

## 6. 起動手順：実機（chibamouse1）

chibamouse1 をまだ作っていなければ、先に `chibamouse/作り方.md` の手順で作る。

1. ロボットの電源を入れ（緑 LED が点いて約43秒で起動する）、**Mac の Wi-Fi を研究用ルータ `<研究用ルータのSSID>` に切り替える**（インターネットは有線の学校 LAN から使える）。
2. Mac のターミナルでロボットにログインし、raspimouse ノードを起動する（chibamouse1 では ROS_DOMAIN_ID は自動で 30 になる）。

   ```bash
   ssh -i ~/.ssh/pimouse_ed25519 ubuntu@<ロボットのIP>
   ```

   ```bash
   ros2 launch raspimouse raspimouse.launch.py
   ```

3. コンテナの Terminator で実機モードにする（ROS_DOMAIN_ID は `ros_domain_id.txt` から 30 が自動で設定される）。**新しい Terminator を開き直してから**次へ進む。

   ```bash
   robot_connect <ロボットのIP>
   ```

4. **車輪を浮かせた状態で**起動し、動きを確かめてから床に置く。起動すると自動でモータの電源が入り、`Ctrl + C` で止めると停止の指令を送ってモータの電源を切る。

   ```bash
   source ~/ros2_ws/install/setup.bash
   ros2 launch finger_dance finger_dance.launch.py
   ```

5. ブラウザで camera.html を開いて「開始」を押す（5章の 2）。
6. 終わるときは、端末で `Ctrl + C` → `robot_disconnect`。ロボットは `sudo poweroff` → 緑 LED が消えてから電源スイッチを切る（**reboot は使わない**。Pi 3 が起動しなくなる）。

## 7. パラメータ

`ros2 launch` の引数：`turtlesim`（false）、`rosbridge_port`（9091）、`view`（true：rqt_image_view を開く）、`mirror`（false）。

ノードを1つずつ動かして細かく変えるときは、`ros2 run finger_dance finger_dance --ros-args -p linear_max:=0.03` のようにする。

| ノード | パラメータ | 既定値 | 意味 |
|---|---|---|---|
| finger_detect | `mirror` | false | 映像が左右反転しているとき、またはロボットを鏡のように動かしたいとき true |
| finger_detect | `ext_ratio` | 1.1 | 指を「伸ばしている」とみなす距離の倍率（1章） |
| finger_detect | `model` | `/opt/finger_dance/hand_landmarker.task` | モデルファイル |
| finger_dance | `turtlesim` | false | true で `/turtle1/cmd_vel`（Twist）に送り、速さの上限を turtlesim 用にする |
| finger_dance | `linear_max` | 0.05（turtlesim 1.0） | 前後の最大速度 [m/s] |
| finger_dance | `angular_max` | 1.0（turtlesim 1.5） | 旋回の最大角速度 [rad/s] |
| finger_dance | `dance_angular`・`dance_period` | 1.0（turtlesim 3.0）・0.4 | 踊りの角速度 [rad/s] と左右を入れ替える間隔 [s] |
| finger_dance | `straight_band`・`side_band` | 10・20 | 真上・真下から ±何度まで旋回しないか、真横から ±何度まで前後に動かないか [度] |
| finger_dance | `timeout` | 0.5 | 検出結果がこの時間 [s] 届かなければ止まる |
| finger_dance | `confirm` | 2 | 走り出す形に切り替えるまでに、続けて同じ形を検出する回数 |
| finger_dance | `smoothing` | 0.5 | 指の向きのなめらかさ（0 = そのまま、1 に近いほどなめらかだが遅れる） |
| finger_dance | `stamped`・`cmd_topic`・`motor_power` | true・`/cmd_vel`・true | 送り先。チバリヨカーでは 10章 |

## 8. うまくいかないとき

| 症状 | 確認すること |
|---|---|
| rqt_image_view に何も出ない | camera.html の「送信した枚数」が増えているか、`?port=9091` を付けたか、launch の端末に rosbridge のエラーがないか。`ros2 topic hz /image_raw/compressed` |
| 手が映っているのに `none` のまま | 手が画面の端で切れていないか、明るさ。手のひらか手の甲がカメラを向くようにする |
| 人差し指だけなのに `other` や `peace` になる | 中指などを深く曲げる。指をカメラに向けると短く見えて判定を誤るので、指は画面と平行に向ける。必要なら `ext_ratio` を変える |
| 左右が逆に感じる | `mirror:=true` |
| 実機が動かない | `ros2 node list` に `/raspimouse` が出るか（ROS_DOMAIN_ID が PC・ロボットとも 30 か、`robot_connect` の後に端末を開き直したか）。モータの電源スイッチ |
| http://localhost:6081 が開かない | `docker ps` で `finger_dance` が動いているか。6081 番をほかが使っていれば `VNC_PORT=6082 docker compose up -d` |

## 9. 確認状況（2026-10-20、Mac Studio）

- 環境：`finger-dance:jazzy` のビルド OK（MediaPipe 1.1.1、NumPy 1.26.4、OpenCV 4.11.0）。`colcon build` OK。
- 指の判定（`hand_shape.py`）と対応表（`mapping.py`）：手の点を作った試験で、手を 0°・45°・90°・135°・180° 回しても形を正しく判定し、向きも回した角度どおりになった。対応表の値も1章の表どおり。踊りの向きの振れは −0.22〜+0.20 rad（turtlesim の 3.0 rad/s では約 ±0.6 rad）で、元の向きを中心に振れる。
- 実際の手の写真（MediaPipe の試験用画像 `pointing_up.jpg`・`victory.jpg`・`fist.jpg`・`thumb_up.jpg`）を 0°・右 90°・左 90°・180° に回して判定：16 枚すべて期待どおり（人差し指 → point、角度 0・+90・−90・180、チョキ → peace、グー → fist、親指を立てた手 → fist（親指は使わないので停止になる））。
- 一連の動作（写真を 640×480・10 fps で `/image_raw/compressed` に送る → `finger_detect` → `finger_dance` → turtlesim）：`/finger_gesture` は約 9.7 Hz で出た。1 枚の処理は、手を追跡している間 約 70 ms、手を見つけ直すとき 約 180〜200 ms。人差し指を上 → 前進、右 90° に回した写真（本人から見て左を指す）→ その場で左回り（約 1.5 rad/s）、グー → 停止、下 → 後退、チョキ → 左右に振る、手なし → 停止、画像が止まる → 0.5 秒で停止、のすべてを確認した。写真を急に切り替えたときに1〜2枚だけ `fist`・`none` になることがあったが、止まる側なので安全である。
- rosbridge（9091）経由：camera.html と同じ手順（advertise → publish）で Mac から写真を送り、検出・前進することを確認した。`http://localhost:6081/camera.html` も開ける。

## 9.5 ロボットと指の認識を並べた動画を作る

iPhone で撮ったロボットの動画と、指の認識の画面（`/finger_image/compressed`）を、時刻を合わせて左右に並べた1本の動画にする。**指の認識の画面は記録しておかないと残らない**ので、撮影の前に記録を始める。

1. 指ダンスを起動し（6章）、コンテナの Terminator で記録を始める（`ros2_ws/bags/` に残る）。

   ```bash
   ros2 bag record -o ~/ros2_ws/bags/dance_$(date +%Y%m%d_%H%M%S) /finger_image/compressed /finger_gesture /cmd_vel
   ```

2. iPhone でロボットを撮りながら、指で操縦する。撮り終わったら、記録の端末で `Ctrl + C`。
3. 記録を MP4 にする（コンテナの Terminator。`<名前>` は 1. で作られたフォルダ）。下に時刻と速度の指令が入る。

   ```bash
   python3 ~/ros2_ws/tools/bag_to_mp4.py ~/ros2_ws/bags/<名前>
   ```

4. iPhone の動画を研究フォルダに置き、Mac のターミナルで並べる。時刻は iPhone の撮影開始時刻と記録の時刻で合わせる（ずれは 1 秒程度。ずれて見えるときは3つ目に補正の秒数を書く。指の認識が遅れて見えるときは +）。

   ```bash
   cd chibariyo-dance-mimic && tools/combine.sh IMG_xxxx.MOV ros2_ws/bags/<名前>_finger.mp4
   ```

   `IMG_xxxx_combined.mp4`（左：ロボット、右：指の認識、音声は iPhone）ができる。ダンスの記録のときは右の見出しを `LABEL='ダンスの検出（MediaPipe）'` で変える。iPhone の動画が横倒しに写るときは `ROTATE=ccw`（左に 90°）か `cw` を付ける（例：`ROTATE=ccw LABEL='ダンスの検出（MediaPipe）' tools/combine.sh robo_dance1.MOV ros2_ws/bags/pose_20261026_142921_dance.mp4`）。

- 2026-10-26 に作った例：`IMG_1235_combined.mp4`（52 秒。記録 `ros2_ws/bags/dance_20261026_112114`、時刻のずれの補正なしで、指の向きとロボットの動きが合っていた）。
- 気づいた点：机に置いたもう一方の手が映っていると、そちらの手（パー）を検出して、立てた人差し指を見ないことがあった（`num_hands=1` で1本の手しか見ないため）。操縦しない手は画面の外に出しておく。改良するなら、2本の手を検出して、人差し指を立てている手を選ぶ。

## 9.6 人のダンスに合わせて踊る（pose_dance、2026-10-26 試作）

カメラの前の人、またはダンスの動画に合わせてロボットを踊らせる。体の 33 点（MediaPipe Pose Landmarker full）から 3 つの動きを取り出し、ロボットの目標にする。ロボットは目標に近づくように v・ω を決める（比例制御）ので、その場から離れていかない。

| 人の動き | ロボットの動き | 主なパラメータ |
|---|---|---|
| 体の向き（両肩の奥行きの差）＋ 腰の左右の揺れ（胴の長さで割る） | ロボットの向き（±60° まで） | `yaw_gain` 0.7、`sway_gain` 60 |
| 腰の上下のはずみ（しゃがむ・伸びる。胴の長さで割る） | 前後に揺れる（±2 cm まで） | `bounce_gain` 0.1 |
| 手首を肩より上に上げる | その側の LED が点く（右手 → LED 0・1、左手 → LED 2・3） | `leds` |
| 体が見えない・0.5 秒検出がない | 止まる | `timeout` |

- ファイル：`video_source.py`（動画を `/image_raw/compressed` に流す）、`pose_detect.py`（体の検出 → `/dance_pose`、`/pose_image`）、`pose_mapping.py`（体の動き → 目標 → v・ω。ROS 2 に依存しない）、`pose_dance.py`（指令・LED・止まる条件）、`launch/pose_dance.launch.py`。分析用：`ros2_ws/analysis/`（`pose_series.py`、`offline_dance.py`）。
- 動画：`ros2_ws/videos/` に Pexels の 3 本（Pexels ライセンス。無料・改変可・クレジット不要）。
  - `pexels_7571381_man_studio.mp4`（Antoni Shkraba、59 秒）、`pexels_7570258_woman_studio.mp4`（Antoni Shkraba、26 秒）、`pexels_6939968_woman_contemporary.mp4`（Pavel Danilyuk、18 秒）
  - ポップ系（2026-10-26 追加）：`pexels_10264579_woman_hiphop.mp4`（21 秒。体の検出 100%、向き −44〜+60°）、`pexels_6322570_man_hiphop.mp4`（33 秒。検出 52%。下から見上げる角度で腰が切れ、7.9〜12.3 秒と 26.1 秒以降は止まる）、`pexels_8027276_woman_freestyle.mp4`（17 秒。検出 74%。11〜15 秒に途切れがある）
  - 体の検出に使うのは両肩・腰・手首なので、膝から下が映っていなくても使える。腰が画面から切れると検出できない。
- 起動（turtlesim）：`ros2 launch finger_dance pose_dance.launch.py turtlesim:=true`。動画を変えるときは `file:=/home/ubuntu/ros2_ws/videos/…`。カメラの前の人に合わせるときは `source:=camera`（カメラページは 5 章と同じ）。`delay:=1.0` で 1 秒遅れて真似る（掛け合い）。
- 起動（ロボット）：6 章の手順で robot_connect の後、指ダンス（finger_dance.launch.py）を止めてから `ros2 launch finger_dance pose_dance.launch.py`。
- 確認：3 本の動画をすべての画像で体を検出できた（1 枚 約 110 ms、1 秒に約 8.5 回）。試算と turtlesim で、ロボットの向きは目標に約 0.3 秒遅れで追従し、向きは −58〜+56°、前後は ±2 cm。ω が上限 1.0 rad/s に当たるのは、動きの速い女性の動画で 22%、男性の動画で 9%。録画：`ros2_ws/bags/pose_dance_turtlesim_demo.mp4`。
- まだ：実機（chibamouse1）での確認、カメラの前の人での確認。Docker のイメージは作り直していない（Pose のモデルは今のコンテナに手で置いた。Dockerfile には足してある）。
- 気づいた点：前後の揺れを、そのときの向きの方向に進むので、長く踊ると少しずつ位置がずれる（turtlesim では 1 分で約 1 マス分）。

## 10. チバリヨカーへの展開の考え方

- `hand_shape.py`（指の判定）と `mapping.py`（対応表）は ROS 2 に依存しないので、そのまま使える。チバリヨカーの環境は ROS 2 Humble（`~/dev/chibariyo`）だが、この2つと2つのノードは Humble でも動くように、rclpy の基本的な機能だけを使って書いた（Humble での動作は未確認）。
- 送り先は、`-p stamped:=false -p cmd_topic:=/cmd_vel -p motor_power:=false`（チバリヨカーの `/cmd_vel` は Twist）と、速さの上限（`linear_max`・`angular_max`・`dance_angular`）を変えるだけでよい。人が乗る・人のそばで動くので、上限はまず小さくして試す。
- チバリヨカーの「踊り物真似」（`dance_mimic_node.py`）は、人の前後速度・旋回速度を少し遅らせて再生する方式である。指の向きから作った速度（`finger_dance` の出力）をその入力にすれば、「指で振り付けを見せる → 車いすが少し遅れて真似る」形にもできる。
- 身体全体の動き（MediaPipe Pose）で操縦する方式は、指の方式で使い勝手を確かめた後に検討する。
