# crowd_demo Re-ID改良と3方式再比較 (2026-10-20, 各180秒 x 3本)

## 最終結果(新シナリオ: 通行人が車椅子を避けて歩く)

| 方式 | ID維持率 | 別人追従 | 見失い率 | 距離維持誤差 |
|---|---|---|---|---|
| reid(改良後) | 96.3 [91.4-96.5] | 0.8 [0.7-1.0] | 3.0 [2.8-7.6] | 0.7 [0.7-0.7] |
| reid(8/23設定) | 78.5 [56.3-80.8] | 17.8 [14.3-40.8] | 3.7 [2.9-5.0] | 0.6 [0.6-0.7] |
| yolo | 53.8 [33.6-76.7] | 42.8 [15.4-59.0] | 7.4 [3.3-7.9] | 0.6 [0.5-0.7] |
| lidar | 58.9 [38.4-59.9] | 41.1 [40.1-61.6] | 0.0 [0.0-0.0] | 0.5 [0.5-0.6] |

各セルは 中央値 [最小-最大] (n=3)。ID維持率/別人追従/見失い率は %、距離誤差は m (目標1.2m)。
ファイル: `summary_f_reid[1-3]_*` / `f_old*` / `f_yolo*` / `f_lidar*`。4条件を1本ずつ交互に回した。

reid(改良後)は ID維持率・別人追従とも他の3条件と範囲が重ならない。
reid(8/23設定)は `hist_min_sim:=0.25 hist_relax:=true depth_sync:=false anchor_update_sim:=0.0 torso_roi:=false`。

**8/23の数値(RESULTS_20260823.md)とは直接比べられない。** 下記の通り、シナリオと実行環境の両方が変わった。

## 8/23から変わった前提

1. **シナリオ**: 通行人(person2)は車椅子の0.35m以内で立ち止まる設定だったが、車椅子の角に接したまま
   双方が動けなくなる相互デッドロックが起きていた(通行人は停止、車椅子は旋回できない。t≈133sで
   発生し計測終了まで約55秒見失いが続く回が複数)。`robot_stop_radius 0.0` + `avoid_radius 1.0`
   (1m以内で車椅子から離れる向きへ進路を曲げる)に変更。通行人が本人の近くを通る時間が増えたため、
   最近傍方式(yolo/lidar)の別人追従は8/23(12.5%/21.2%)より大幅に悪化した。
2. **実行環境**: Dockerイメージを再ビルドした(ros_gzがarm64でもaptで入るようになった、
   ultralytics 8.4.183 / torch 2.14.1)。180秒の計測が実時間約4分で終わり、YOLOの処理レートは
   約3-5Hz。8/23と同設定のreidでもID維持率 61.5 [53.3-85.2]% (旧シナリオ)で、8/23の19.1%とは別物。

## 見つかった不具合と対策(yolo_reid_follower_node.py)

診断トピック `/follower/debug`(毎フレームの候補・類似度・棄却理由)と、metrics_logger 側で
真値の相対位置を添えた `debug_<label>_*.jsonl` を追加して原因を切り分けた。

| 問題 | 証拠 | 対策(パラメータ) |
|---|---|---|
| RGBと深度の時刻ずれ | 同じ人の距離が2.6m⇔6.5mと交互に跳ね、本人候補の5%が深度1.5m以上ずれていた | 同じstampの深度を使い、深度が後に届いたRGBは保留して到着後に処理(`depth_sync`)。単純に捨てると処理レートが3割落ちた |
| 色の記憶が通行人に染まる | 本人に似た通行人(類似度0.6-0.7)を受理→EMA更新→本人が正面3.2mに戻っても類似度0.32で棄却され21秒見失い | ロックオン時の原本に0.7以上似ているときだけ記憶を更新(`anchor_update_sim`) |
| 色の下限が実質効かない | 見失い時間に応じて下限を最大1/4まで緩めており、追従中でも0.46。本人に重なった通行人(類似度0.37-0.50)を位置スコアだけで受理し19.5秒別人追従 | 緩和を既定で無効(`hist_relax`)、下限を0.25→0.55(`hist_min_sim`) |
| 近距離で本人の色が変わる | 色領域が「ボックス上から15-55%」で、1m以内ではボックス上端が画面外に切れて別の部位を見ていた。本人の類似度が0.5mで0.47、1mで0.67まで低下し通行人と重なった | 色領域を床から0.95-1.35mの帯が写る行にする(深度とカメラ高さ0.67mからピンホール投影、`torso_roi`) |

torso_roi 後の類似度(カメラ距離1-3m): 本人 p5 0.83以上、通行人 中央値0.14-0.28。

### 注意(書類に使う前に読むこと)

- 胴体帯 0.95-1.35m は、通行人の赤帯(床から0.98-1.33m)の位置を知った上で決めた。成人の胸の高さとして
  不自然な値ではないが、このシナリオでは「通行人を見分ける唯一の手がかり」にちょうど合わせた形になっている。
  服の柄・色が違う別のシナリオでの検証はまだ無い。
- 0.55 の下限も同じシナリオの分布から選んだ(本人の棄却2.3%、通行人の通過5.5%; torso_roi 前の分布)。

## 効果が出なかったもの

# 服装違いでの検証 (2026-10-20 午後, reid改良後 + ヒストグラム平滑化, 各180秒 x 3本)

上の結果は「通行人だけが胸に赤帯」という1種類の服装でしか確かめていなかった。色領域(床から0.95-1.35m)と
色の下限(0.55)はその服装を見て決めたので、服装だけを変えた5つのワールドで汎化を確かめた。
ワールドは `worlds/make_clothing_variants.py` で crowd_test.world から生成(人の動き・部屋・センサは同一)。
起動は `crowd_demo.launch.py world:=crowd_<variant>.world`。

| swap | 赤帯 胸 | 無地 | 96.0 [95.3-96.0] | 1.1 [0.5-1.4] | 3.3 [2.9-3.5] |

## 見つかった不具合: 色付きの服を着た本人を見失う(swap 平滑なし ID 23%)

本人が赤い服だと、本人どうしの類似度が0.2-0.9の間で揺れて21%のフレームで色の門に棄却された。
赤い画素の彩度は照明と向きによってフレームごとに平均172-194の間で動き、32分割(幅8)の彩度ビンの境界を
またぐたびに類似度が落ちていた。無地(灰色)の本人は彩度がほぼ0で1つのビンに収まるため、元のシナリオでは
表に出なかった。

対策: ヒストグラムを色相(循環として扱う)・彩度の両方向にガウスぼかし(幅2ビン、`hist_blur`。0で旧挙動)。
swap の本人の切り抜きで方向を分けて調べると、本人どうしの類似度の p5 は、平滑化なし0.14、色相方向のみ0.14、
彩度方向のみ0.42、両方向0.42で、効いているのは彩度方向である。

(訂正: 当初「色相がビン0と1にまたがって揺れる」と書いたが、ビン1に入っていたのは色領域に写り込んだ腕の
肌色の画素で、原因ではなかった。)

## 特徴量の選び方(オフライン比較)

6ワールドで色領域の切り抜きを真値ラベル付きで集め(`tools/reid_eval/collect.py`, 計1995枚)、
ロックオン相当の原本5枚との類似度で本人と通行人をどれだけ分けられるかを比べた(`tools/reid_eval/evalfeat.py`)。
値は AUC / 本人の棄却を5%に抑えたときの通行人の通過率。

| 特徴 | test | swap | high | pants | similar | identical |
|---|---|---|---|---|---|---|
| H30×S32(平滑なし) | 1.00 / 0% | 0.88 / 89% | 0.99 / 5% | 0.84 / 58% | 1.00 / 0% | 0.32 / 100% |
| H16×S4 | 1.00 / 0% | 0.90 / 77% | 0.99 / 4% | 0.84 / 62% | 1.00 / 0% | 0.43 / 99% |
| **H30×S32+平滑(採用)** | 1.00 / 0% | **1.00 / 3%** | 0.99 / 4% | 0.85 / 60% | 1.00 / 0% | 0.48 / 100% |
| H12×S4×V4 | 1.00 / 0% | 0.95 / 34% | 0.90 / 47% | 0.69 / 83% | 1.00 / 0% | 0.37 / 100% |
| H8×S3×V3 | 0.99 / 10% | 1.00 / 0% | 0.84 / 82% | 0.68 / 86% | 1.00 / 0% | 0.69 / 92% |
| Lab平均 | 0.98 / 10% | 0.98 / 9% | 0.89 / 40% | 0.57 / 83% | 0.89 / 74% | 0.33 / 97% |

平滑化だけが swap を直し、他の条件を悪化させなかった。明度を入れると similar は分けられるが、他が悪化する。

注意: 収集時、真値は推論中に受信が詰まり画像より0.3-0.4秒古くなることがあった。そのため真値は全件を
書き出し、画像の時刻に合わせてオフラインでラベル付けした(`label.py`)。同じ詰まりは reid ノードの
`/odom` 購読(予測探索が使う)にも起きているはずで、予測探索に効果が出なかった一因の可能性がある(未検証)。

## わかったこと(限界を含む)

- 本人・通行人のどちらが色付きでも、色相が近い服(水色と紺)でも、通行人の柄が色領域から一部ずれても、
  別人追従は0.9-2.3%に収まった。元の服装だけに合わせた設計ではなかった。
- **違いが色領域の外にしかない場合(pants)は弱い。** 別人追従 6.9 [6.8-14.3]%。胴体だけを見る設計の限界。
- **同じ服(identical)は見分けられない。** 別人追従 22.4 [6.6-31.4]%。それでも最近傍方式(yolo 42.8%,
  lidar 41.1%, 上の新シナリオの表)より低いのは、位置の連続性が効いているため。
- 平滑化の有無で元のシナリオの成績は変わらない(平滑なし 96.3/0.8%、平滑あり 95.3/0.9%)。
