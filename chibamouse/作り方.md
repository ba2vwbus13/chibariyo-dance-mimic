# 研究用ロボット chibamouse1 の作り方（Raspberry Pi Mouse V3 ＋ Raspberry Pi 3）

作成：2026-10-20、更新：2026-10-22（研究用 Wi-Fi ルータを分けた）（Mac Studio）

専攻科実験の Raspberry Pi Mouse（pimouse1〜3）とは分けて、研究用のロボット **chibamouse1** を1台作る手順である。SD カードは、専攻科実験で作ったイメージを研究用に複製したものから作る（ソフトを一から入れ直す必要はない）。

## 1. 決めたこと

| 項目 | 内容 |
|---|---|
| ロボット | Raspberry Pi Mouse **V3** ＋ Raspberry Pi 3 Model B |
| 名前 | **chibamouse1** |
| Wi-Fi ルータ | **研究用ルータ `<研究用ルータのSSID>`**（研究室に置く。授業用の `<授業用ルータのSSID>` とは別） |
| IP アドレス | **<ロボットのIP>**（`<研究用ルータのSSID>` の DHCP 手動割当。ルータの番地は初期設定（<ルータが配るIP>）のまま使う。Mac は一度に片方のルータにしかつながないので、授業用ルータと番地が同じでも困らない） |
| 覚えさせる Wi-Fi | `<研究用ルータのSSID>` と、先生の自宅の `<自宅のルータのSSID>`。授業用の `<授業用ルータのSSID>` は、作り変えの最後に消す（`chibamouse-wifi`） |
| ROS_DOMAIN_ID | **30**（ロボットの `~/.bashrc` に書くので、ログインすると自動で設定される。授業用のロボットは学生が毎回設定する） |
| 元のイメージ | `~/chibamouse_image/chibamouse_base_20261020.img`（Mac Studio。専攻科実験の `~/pimouse_image/pimouse_20261005.img` を APFS の複製（`cp -c`）で写したもの。11.3GB、16GB 以上のカードに入る） |
| 中身 | Ubuntu Server 24.04（カーネル固定）、ROS 2 Jazzy、rmw_zenoh（Zenoh ルータが自動起動）、Raspberry Pi Mouse のドライバ（Pi 3 用）、raspimouse ノード。詳しくは専攻科実験の引き継ぎ書 5章 |
| 名前の付け替え | `chibamouse-setname`（このフォルダ）。専攻科実験の `pimouse-setname` を元に、名前を自由に付けられるようにし、ROS_DOMAIN_ID を `~/.bashrc` に書くようにした |
| Wi-Fi の付け替え | `chibamouse-wifi`（このフォルダ）。`/etc/netplan/` の Wi-Fi の一覧を見る・足す・消す。パスワードは画面に出さずに入力する。複製した SD カードでは cloud-init が `system-boot` の `network-config` を読み直さないので、Mac でそのファイルを書き換えても効かない |

- ドライバは Pi 3 向けにビルドしたもので、マウス本体の V2・V3 には左右されない。raspimouse ノードは既定（`use_pulse_counters` が false）では指令値からオドメトリを計算するので、V2 と同じ手順で動く。V3 はパルスカウンタで車輪の回転を実測できるので、動きを評価するときに使うとよい（未確認）。
- 授業用のイメージ（`~/pimouse_image/`）と授業用のフォルダには手を加えない。
- 研究室には、研究室用のルータと研究用ルータ `<研究用ルータのSSID>` の2台を置く。**Raspberry Pi の実験のときは、Mac の Wi-Fi を `<研究用ルータのSSID>` に切り替える。** インターネットは有線の学校 LAN から使えるので、切り替えても困らない。Mac が研究室用ルータに自動で戻ると実験中に通信が切れるので、システム設定の Wi-Fi で研究室用ルータの「自動接続」を切っておく。
- Mac の Wi-Fi は一度に1つのネットワークにしかつながらない。USB の Wi-Fi ドングル（PLANEX など）は、今の macOS（Apple シリコン）では動くドライバがないので使えない。

## 2. 用意するもの

- Raspberry Pi Mouse V3（Pi 3 を載せたもの）、16GB 以上の microSD カード（研究用とラベルを貼る）、Mac のカードリーダ
- Mac Studio（有線で学校 LAN にもつながっている）
- 授業用ルータ `<授業用ルータのSSID>`（4章だけ使う。複製したばかりの Pi はこのルータしか知らないため）と、研究用ルータ `<研究用ルータのSSID>`（2.4GHz を有効にし、端末どうしの通信を遮断する「隔離機能」を切っておく。Pi 3 は 2.4GHz にしかつながらない）
- **pimouse1〜3 の電源は切っておく**（作り変える前の複製は名前・machine-id が pimouse1 と同じなので）

## 3. SD カードに書き込む（Mac、約7分）

1. カードを Mac に挿す。「初期化」などのダイアログが出ても押さない（「無視」）。
2. カードのディスク番号を確かめる。容量（16GB、32GB など）で見分ける。Mac Studio 本体の SD カードスロットに挿した場合は「**internal**, physical」と表示される（`diskutil info diskN` の Device / Media Name が「Built In SDXC Reader」。2026-10-20 は disk4 だった）。USB のカードリーダなら「external, physical」。**番号を間違えると Mac のディスクを消すので、毎回確かめる。**

   ```bash
   diskutil list
   ```

3. 書き込む（`N` は 2. の番号。パスワードを聞かれる）。

   ```bash
   diskutil unmountDisk /dev/diskN
   ```

   ```bash
   sudo dd if=$HOME/chibamouse_image/chibamouse_base_20261020.img of=/dev/rdiskN bs=4m status=progress
   ```

4. 終わったら取り出す。

   ```bash
   diskutil eject /dev/diskN
   ```

Raspberry Pi Imager は、保存された設定（名前など）を上書きするおそれがあるので使わない。

## 4. 初めて起動して chibamouse1 に作り変える

**この章だけは、授業用ルータ `<授業用ルータのSSID>` の電源を入れ、Mac の Wi-Fi も `<授業用ルータのSSID>` につなぐ。**（複製したばかりの Pi は、このルータと先生の自宅の Wi-Fi しか知らない。）

1. カードを V3 の Pi 3 に挿し、電源を入れる。初回はカードいっぱいに区画を広げるので、ふだん（約43秒）より時間がかかる。Pi は `<授業用ルータのSSID>` につながり、仮の IP（.2〜.65 のどれか）をもらう。
2. Mac のターミナルで Pi の IP を探す（Zenoh ルータの 7447 番が開いている機器を探す。1〜2分待ってから実行する）。

   ```bash
   for i in $(seq 2 65); do (nc -z -G 1 <ネットワークの番号>.$i 7447 2>/dev/null && echo "<ネットワークの番号>.$i") & done; wait
   ```

3. 名前と Wi-Fi を付け替えるスクリプトを Pi に送ってログインする（`IP` は 2. で出た IP。鍵は専攻科実験で全台に入れた `~/.ssh/pimouse_ed25519`）。

   ```bash
   scp -i ~/.ssh/pimouse_ed25519 chibariyo-dance-mimic/chibamouse/chibamouse-setname chibariyo-dance-mimic/chibamouse/chibamouse-wifi ubuntu@IP:/tmp/
   ```

   ```bash
   ssh -i ~/.ssh/pimouse_ed25519 ubuntu@IP
   ```

4. Pi の中で、スクリプトを入れて名前を付け替える（セットアップ用にパスワードなしの sudo が入っている）。最後に **wlan0 の MAC アドレス**が表示されるので控える。

   ```bash
   sudo install -m 755 /tmp/chibamouse-setname /tmp/chibamouse-wifi /usr/local/sbin/
   sudo chibamouse-setname chibamouse1 30
   ```

5. 研究用ルータの Wi-Fi を覚えさせる。`<研究用ルータのSSID>` の**パスワードを聞かれるので、先生が入力する**（打っても画面には出ない）。終わったら一覧に `<研究用ルータのSSID>` が出ることを確かめて、電源を切る。

   ```bash
   sudo chibamouse-wifi add <研究用ルータのSSID>
   sudo chibamouse-wifi list
   sudo poweroff
   ```

6. 緑の LED が消えたら電源を切る（**reboot は使わない**。Pi 3 が起動しなくなる。専攻科実験の引き継ぎ書 5章）。授業用ルータ `<授業用ルータのSSID>` は、もう使わない。

## 5. 研究用ルータに IP を登録する（先生）

1. **Mac の Wi-Fi を `<研究用ルータのSSID>` に切り替え**、Mac のブラウザで http://<ルータのIP> を開く（管理パスワードはルータ本体のシール）。画面の名前は機種によって違う（下は WSR-2533DHP の例）。
2. 「詳細設定」→「LAN」→「DHCP リース」→「**リース情報の追加**」で、IP アドレス `<ロボットのIP>`、MAC アドレス（4. の 4 で控えたもの）を登録する。「手動割当に変更」は今の IP のまま固定するボタンなので使わない。
3. Pi の電源を入れる。約43秒で起動し、`<研究用ルータのSSID>` につながって <ロボットのIP> になる。

MAC アドレスは Pi の基板のものなので、Pi を別のロボットに付け替えると IP もついていく。

## 6. ログインと動作の確認

1. ホスト鍵が変わったので、Mac に残っている古い記録を消してからログインする。

   ```bash
   ssh-keygen -R <ロボットのIP>
   ```

   ```bash
   ssh -i ~/.ssh/pimouse_ed25519 ubuntu@<ロボットのIP>
   ```

   つながったら、授業用ルータの Wi-Fi を消して、研究用ルータ（と先生の自宅）だけにする。消すのは、研究用ルータにつながることを確かめた後にする（先に消すと、パスワードを打ち間違えていたときに Pi に入れなくなる）。次に電源を入れたときから使われる。

   ```bash
   sudo chibamouse-wifi remove <授業用ルータのSSID>
   sudo chibamouse-wifi list
   ```

   毎回の入力を省くには、Mac の `~/.ssh/config` に次を足す（以後は `ssh chibamouse1` で入れる）。

   ```
   Host chibamouse1
       HostName <ロボットのIP>
       User ubuntu
       IdentityFile ~/.ssh/pimouse_ed25519
   ```

2. ロボットで raspimouse ノードを起動する（ROS_DOMAIN_ID は自動で 30 になっている。`echo $ROS_DOMAIN_ID` で確かめられる）。

   ```bash
   ros2 launch raspimouse raspimouse.launch.py
   ```

3. 研究用コンテナ（http://localhost:6081 の Terminator）で実機モードにし、**新しい Terminator を開き直して**光センサの値が届くか確かめる。

   ```bash
   robot_connect <ロボットのIP>
   ```

   ```bash
   ros2 topic echo --once /light_sensors
   ```

4. **車輪を浮かせて**モータを確かめる（0.05 m/s で2秒進めて止める）。

   ```bash
   ros2 service call /motor_power std_srvs/srv/SetBool "{data: true}"
   timeout 2 ros2 topic pub -r 10 /cmd_vel geometry_msgs/msg/TwistStamped "{twist: {linear: {x: 0.05}}}"
   ros2 topic pub --once /cmd_vel geometry_msgs/msg/TwistStamped "{}"
   ros2 service call /motor_power std_srvs/srv/SetBool "{data: false}"
   ```

5. ここまで動けば、指ダンス（`../README.md` の 6章）に進む。
6. 終わるときは、ロボットで `sudo poweroff` → 緑 LED が消えてから電源を切る。

## 7. うまくいかないとき

| 症状 | 確認すること |
|---|---|
| 4. の 2 で IP が出ない | 2〜3分待ってからもう一度。ルータの「DHCP リース」の一覧に `pimouse1` という名前の新しい機器が出ていればその IP。カードの書き込みをやり直す |
| ssh で `REMOTE HOST IDENTIFICATION HAS CHANGED` | `ssh-keygen -R <IP>` をしてから入り直す |
| 5. の後、<ロボットのIP> が見つからない | Mac の Wi-Fi が `<研究用ルータのSSID>` になっているか。`<研究用ルータのSSID>` のパスワードの打ち間違いが考えられる：`<授業用ルータのSSID>` の電源を入れ、Mac もそちらにつなぎ、4. の 2 の方法で Pi を探して入り、`sudo chibamouse-wifi remove <研究用ルータのSSID>` → `sudo chibamouse-wifi add <研究用ルータのSSID>` でやり直す。Mac が研究室用ルータに戻っていないか |
| <ロボットのIP> にならない | ルータに登録した MAC が 4. で表示されたものと同じか。登録の後、電源を入れ直したか。同じ IP の機器（固定 IP のテプラなど）がいないか（`arp -an`。専攻科実験の引き継ぎ書 11章） |
| `/light_sensors` が届かない | ロボット側の raspimouse ノード、`robot_connect` の後に端末を開き直したか、PC 側の `echo $ROS_DOMAIN_ID` が 30 か |
| 車輪が回らない | モータ用の電源スイッチ、`/motor_power` を true にしたか、`/cmd_vel` が TwistStamped か |
| Pi が起動しない（赤 LED だけ点く） | reboot をしていないか。電源を切って入れ直すと起動する |
