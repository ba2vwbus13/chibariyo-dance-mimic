# WHILL Model CR を踊らせる・指で操縦する

作成：2026-11-02（指で操縦する方法は 2026-11-04 に追加）

人のダンスに合わせて踊る仕組み（pose_dance）と、指の動きで操縦する仕組み（finger_dance）を、WHILL Model CR（研究開発用の電動車いす）で動かす。Model CR は RS232C のシリアル通信で外から操作でき、WHILL 社の Python のライブラリ pywhill（`pip install whill`）で指令を送る。

## 1. 仕組み

```
コンテナ（ROS 2 Jazzy）                           MacBook（Docker の外）                 Model CR
 video_source → pose_detect → pose_dance ──/cmd_vel（Twist）──→ whill_bridge.py ──RS232C──→ ジョイスティックの指令
                                 robot:=whill        rosbridge 9091     （pywhill）
```

- Docker Desktop のコンテナからは USB のシリアルを使えないので、車いすとの通信は MacBook の上で直接動かす `whill_bridge.py` が行う。
- `whill_bridge.py` は、速度の指令を**ジョイスティックの倒し量**（−100〜100）に直して送る。車いすの速度モードと加減速の設定がそのまま効く。
- 指で操縦するときは、`video_source → pose_detect → pose_dance` の代わりに、`camera.html → finger_detect → finger_dance robot:=whill` が `/cmd_vel` を送る。`whill_bridge.py` は同じものを使う。
- pywhill の説明では、`side` が + のとき右に回る。ROS は左回りが + なので、符号を逆にして送る（`--side-sign -1`）。

## 2. 安全のための決まり

| 決まり | 内容 |
|---|---|
| 人を乗せない | 試験の間は誰も乗せない |
| 周りを空ける | 車いすの周り 1 m 以上に物や人がいないようにする |
| 電源ボタン | 指令を送っている間は車いすのジョイスティックが効かない。いざというときは**車いすの電源ボタン**を押す。押せる人がそばにいる |
| 速さの制限 | 倒し量は旋回 ±10%、前後 0%（前後に動かない）から始める。上限は 20%。後ろ向きは前向きの 3 倍（`--back-gain`）にする。Model CR は同じ倒し量だと、後退が前進の 1/3 ほどの速さしか出ないため |
| ゆっくり動き出す | 倒し量は 1 秒に 20% までしか増やさない。後ろ向きは 3 倍の 1 秒に 60% までとする（車いすの速さの上がり方は前進と同じ）。止めるときはすぐ 0 にする。向きが逆になるとき（左回り → 右回りなど）は、一度 0 にしてから増やす |
| 指令が途切れたら止まる | 指令が 0.3 秒届かない、rosbridge が切れた、踊りや指の操縦のプログラムが止まった、のどれでも止まる。指で操縦するときは、手が映らない・グー・パーでも止まる |
| 停止キー | MacBook の端末で Enter を押すと停止・再開を切り替える。Ctrl + C で終わるときは止めてからジョイスティックを戻す |

## 3. 手順

### 3.1 準備（MacBook、初回だけ）

踊りのプログラムも MacBook で動かす。Docker Desktop を入れて起動し、リポジトリを取ってコンテナを作る（初回はインターネットで約 3 GB を取り、20〜30 分かかる）。

```bash
git clone https://github.com/ba2vwbus13/chibariyo-dance-mimic.git
cd chibariyo-dance-mimic && tools/download_videos.sh
cd docker && docker compose up -d --build
```

ブラウザで http://localhost:6081 を開き、デスクトップの Terminator でビルドする。

```bash
cd ~/ros2_ws && colcon build --symlink-install
```

MacBook の端末（Docker の外）で、車いすとの通信に使うライブラリを入れる。

```bash
pip3 install whill websocket-client
```

USB-RS232C のケーブルで Model CR と MacBook をつなぎ、装置名を調べる（`/dev/cu.usbserial-XXXX` のような名前）。

```bash
ls /dev/cu.usbserial*
```

### 3.2 つながるかの確認（動かさない）

車いすの電源を入れてから実行する。電池の残り・速度モード・左右のモータの速さが 5 秒表示されれば、つながっている。

```bash
python3 whill_check.py --port /dev/cu.usbserial-XXXX
```

### 3.3 ごく小さく動かす確認

人を乗せず、周りを空けてから実行する。`yes` と入力すると、ジョイスティック 8% で 1 秒ずつ、前進・`side +`・`side −` の順に動いて止まる。`side +` で右に回れば、pywhill の説明どおりである。

```bash
python3 whill_check.py --port /dev/cu.usbserial-XXXX --test-move
```

### 3.4 踊らせる

コンテナの Terminator で、踊りを `robot:=whill` で起動する（向き ±30°、前後 ±5 cm、前後の速さ 0.1 m/s・旋回の速さ 0.3 rad/s まで）。

```bash
ros2 launch finger_dance pose_dance.launch.py robot:=whill file:=/home/ubuntu/ros2_ws/videos/pexels_10264579_woman_hiphop.mp4
```

MacBook の端末（Docker の外）で、リポジトリの `whill` フォルダに移って橋渡しを動かす。最初は旋回だけで試す。

```bash
python3 whill_bridge.py --port /dev/cu.usbserial-XXXX
```

旋回がうまくいったら、前後の揺れも少しだけ足す。

```bash
python3 whill_bridge.py --port /dev/cu.usbserial-XXXX --front-cap 5
```

前後の揺れを足すと、後退が前進より弱いので、少しずつ前に進む（20 秒で 20 cm ほど）。長く踊らせるときは、旋回だけにする。

車いすにつながずに、送る値だけを確かめるときは `--dry-run` を付ける。

### 3.5 指で操縦する

指の形と人差し指の向きで、車いすを走らせる・旋回させる・その場で左右に振る。対応表は Raspberry Pi Mouse と同じである（作業記録の 1 章）。

| 手の形 | 車いすの動き |
|---|---|
| 人差し指だけを伸ばす | 指の向きで走る。真上で前進、真横でその場で旋回、真下で後退、斜めはその間 |
| チョキ | その場で左右に振る（1.0 秒ごとに左右を入れ替える） |
| グー・パー・その他の形・手が映っていない | 止まる |

`robot:=whill` にすると、速さの上限が `whill_bridge.py` の既定値と同じ前後 0.1 m/s・旋回 0.3 rad/s になり、送り先が `/cmd_vel`（Twist）になる。指を真上に向けると前後の倒し量が `--front-cap` に、真横に向けると旋回の倒し量が `--side-cap` になる。

1. コンテナの Terminator で、指の操縦を `robot:=whill` で起動する。

   ```bash
   ros2 launch finger_dance finger_dance.launch.py robot:=whill
   ```

2. MacBook のブラウザ（Chrome）で http://localhost:6081/camera.html?port=9091 を開き、カメラを選び、10 fps にして「開始」を押す。カメラの前で手を動かし、rqt_image_view に手の点と判定が出ることを確かめる。
3. MacBook の端末（Docker の外）で、まず `--dry-run` で送る値を確かめる。人差し指を上に向けると前後が +、左に向けると旋回が −（左回り）になる。

   ```bash
   python3 whill_bridge.py --dry-run --front-cap 8
   ```

4. 人を乗せず、周りを空けてから、最初は旋回だけで試す（前後 0%）。指を左右に向けて旋回し、チョキで左右に振ることを確かめる。

   ```bash
   python3 whill_bridge.py --port /dev/cu.usbserial-XXXX
   ```

5. 旋回がうまくいったら、前後も動かす。前進の倒し量 8%（3.3 で約 0.5 km/h まで上がった値）から始める。後ろ向きは `--back-gain 3` で 24% になるが、上限の 20% で止まる。

   ```bash
   python3 whill_bridge.py --port /dev/cu.usbserial-XXXX --front-cap 8
   ```

- 操縦する人は MacBook のカメラの前にいるので、車いすから離れる。**車いすの電源ボタンを押せる人を、別にそばに置く。**
- 「左」は、カメラの前の人から見た左である。車いすと人が向かい合っていて、鏡のように動かしたいときは `mirror:=true` を付ける。
- 操縦しない手は画面の外に出す。机に置いた手（パー）を見て、止まることがある。

## 4. 確認状況

- `whill_bridge.py --dry-run` と `pose_dance robot:=whill`（ヒップホップの動画）を Mac Studio で動かし、指令が倒し量 ±10% に収まること、左回りが `side −` になること、踊りのプログラムを止めると 0 を送ることを確かめた（2026-11-02）。
- MacBook と Model CR を USB-RS232C（Prolific、`/dev/cu.usbserial-110`）でつなぎ、`whill_check.py` で電池 100%・速度モード 0 が読めることを確かめた（2026-11-02）。挿し直した直後の 1 回目は、値が全部 0 だった。
- pywhill 1.5.0 の `stop_data_stream()` は、長さの表に STOP がなく KeyError になる。`whill_check.py` と `whill_bridge.py` では、STOP を直接送るようにした（2026-11-02）。
- `whill_check.py --test-move`（倒し量 8%）を人を乗せずに動かした（2026-11-02）。前進では左 +0.48 km/h・右 −0.48 km/h まで上がり、0.4 秒ほどで止まった。`side +` では左右とも +0.03 km/h ほどで、目で見て 5 cm ほど右に曲がった。pywhill の説明どおりなので、`--side-sign -1` のままでよい。8% では旋回がごく小さい。
- 倒し量を 12% にした（2026-11-02）。前進では左 +0.70 km/h・右 −0.68 km/h まで上がった。旋回では `side +` が +0.07 km/h ほど、`side −` が −0.09 km/h ほどで、目で見て 10 cm ほど右に行ってから左に戻った。1 秒ではまだ速さが上がっている途中である。
- 上の USB-RS232C は ELECOM の製品（USB の番号 056E:5004、中は Prolific）だった。初めは Prolific の番号（067B:2303）で見えて使えたが、途中から ELECOM の番号で見えるようになり、装置名ができなくなった。ELECOM は Mac 用のドライバを出していないので、FTDI の部品を使った変換ケーブル（0403:6001、`/dev/cu.usbserial-FTF5VWT4`）に替えた。Mac に最初から入っているドライバで使える（2026-11-02）。
- `whill_bridge.py`（旋回 ±10%、前後 0%）と `pose_dance robot:=whill`（ヒップホップの動画）で、人を乗せずに 20 秒ずつ 2 回踊らせた（2026-11-02）。指令は途切れず、左右のモータは −0.10〜+0.10 km/h、前後は 0% のままで、目で見て左右に揺れた。Ctrl + C で止めると 0 を送り、ジョイスティックが戻った。
- 端末から離して裏で動かすと Ctrl + C（SIGINT）が効かず、止める処理が走らない。そのときは SIGINT を受け付けるように戻してから動かす。
- `--front-cap 5 --side-cap 15` で 20 秒踊らせた（2026-11-02）。左のモータは −0.16〜+0.38 km/h、右は −0.45〜+0.23 km/h まで出たが、後ろには行かず、20 秒で 40 cm ほど前に進んだ（モータの速さから計算）。後退 8% だけを 1 秒送ると 0.15 km/h で頭打ちになり、前進 8% の 0.48 km/h の 1/3 ほどだった。速度モード 0 の設定では、前進と後退の最高速度・加速は同じ値（10 と 16）である。
- 後ろ向きの倒し量を 3 倍（`--back-gain 3`）にし、増やす速さも 3 倍にした（2026-11-02）。後ろへも 0.29 km/h まで動くようになったが、前へのずれは 20 秒で 23 cm ほど残った（倒し量だけ 3 倍にしたときは、目で見てもまだ前に進んだ）。倒し量を 4 倍にしても、送る値は変わらなかった。後退 15% で後退の速さが伸びるかは、まだ測っていない。
- 指で操縦する方法を WHILL 向けにした（2026-11-04、Mac Studio、車いすにはつながない）。`finger_dance` に `robot:=whill` を足し、MediaPipe の試験用の手の写真（人差し指を 0°・左 90°・右 30°・180° に回したもの、チョキ、グー）を 10 fps で送って、`whill_bridge.py --dry-run --front-cap 8` の値を確かめた。人差し指を上 → 前後 +8%、左 90° → 旋回 −10%（左回り）、右 30° → 前後 +7%・旋回 +5%、下 → 前後 −20%、チョキ → 旋回 ±10% を 1.0 秒ごとに入れ替え、グー → 0%、写真を止める → 0% になった。倒し量は 0.1 秒に 2%（後ろ向きは 6%）ずつ増えた。写真を切り替えた直後に 1 回だけグーと判定して止まったが、止まる側なので安全である。
- 上の確認で、チョキの左右の入れ替えのとき、旋回の倒し量が +10% から −10% に 0.1 秒で飛んでいた。大きさが同じなので「増やすときはゆっくり」が効かなかったためである。向きが逆になるときは一度 0 にしてから増やすように `whill_bridge.py` を直した（2026-11-04）。直した後は、0 から 0.5 秒で ±10% まで上がり、1 秒ごとに入れ替わった。同じヒップホップの動画の踊り（`--front-cap 5 --side-cap 15`、30 秒）で直す前と比べると、旋回の倒し量の上限 15% と前後の値は変わらず、旋回の大きさの平均が 5.6% から 4.7% に小さくなった（送る値だけの比較。車いすでは確かめていない）。
- 指の操縦で、まだ車いすを動かしていない。
